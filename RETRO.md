# Sprint retrospective

Date: 2026-11-19

## What helped

- One branch and one pull request per task kept create, list, and export reviewable.
- Registering each task before its implementation commit produced Spec trailers on those commits.
- Pytest mapped one test to each acceptance criterion, so the pull requests could check the AC boxes honestly.

## What hurt

- The evidence window is short, so deploy and demo notes were written immediately after the three merges.
- The stretch UI stayed in draft. A CLI and HTTP demo still covers the core acceptance criteria.
